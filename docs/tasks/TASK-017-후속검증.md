## 결함 재현과 수정

- 설치본→현재 제출 Worker 코드(합성 인증·DB 응답) 통합 검사를 추가했다. 최초 제출 저장 또는 저장 후 재조회가 401일 때 상단은 로그인 상태를 유지하고 폼이 숨겨져, 로그아웃으로 대기 제출을 버리지 않으면 재로그인할 수 없었다. 수정 전 expired-save/expired-read 두 사례의 로그인 폼 표시 assertion이 실패했다.
- submission-http.js에서 HTTP 상태를 오류에 보존하고 401을 같은 계정 재로그인 안내로 표시한다. submission-panel.js는 현재 제출 flow의 401일 때만 로그인 토큰/표시를 만료 처리한다. 대기 payload·sessionId·계정 결속은 유지한다.
- 수정 후 같은 계정 재로그인으로 동일 요청을 재시도하고 실제 Worker 코드가 중복을 한 행으로 처리함을 확인했다. 다른 계정 로그인은 인증 전송 전에 거절한다. 실패 뒤 추가 편집한 화면 입력은 유지하되 재시도는 최초 스냅샷을 사용한다.
- AI 429/503 뒤 읽기·Retell·저장·직접 수정본 저장을 계속할 수 있고, 읽기 중 강제로 버튼을 활성화해도 추가 AI 요청이 나가지 않는 설치본 검사를 추가했다. 모델·실환경 DB 호출은 없다.

## 실제 Chrome 검증 중단과 이어갈 절차

- 사용자에게 네트워크 차단 검토본의 별도 Chrome 검증 프로필 설치를 설명했고 「별도 검증 프로필 설치 허용」 답변을 받았다. 설치 전 원래 Chrome 창을 선택하려는 단계에서 도구가 현재 URL을 충분히 확신할 수 없다고 보고하며 Computer Use를 종료했다. 설치·프로필 생성·화면 조작·사용자 입력 삭제는 수행하지 않았다.
- 이 오류를 검증 성공이나 사용자 승인 거절로 보고하지 않는다. 다른 UI 자동화로 제약을 우회하지 않는다. 실제 재열기 보류도 그대로다.
- 사용자 수동 또는 제어 도구 복구 후, 기존 미저장 입력을 보존하고 별도 프로필에 review-02를 설치한다. 직접 만든 합성 글에서 글 연결→구조화→Retell 가림→재확인/종료 복원, 탭/URL 전환, 키보드·좁은 폭·라이트/다크를 확인한다. 각 항목의 수행/실패/미수행만 기록한다.
- 원격 새 후보 확인은 auth-01로 합성 제출·직접 수정·저장 후 재로그인 재조회부터 한다. 오프라인 재시도는 입력 유지·원래 요청·최초본 한 건·추가 수정 미전송을 확인한다. 실제 계정 만료/권한 위조는 승인된 테스트 환경·계정으로 별도 확인한다.
- AI 흐름의 기존 사용자 정상 보고를 반복 요청하지 않는다. 수정본 또는 의미 안전성 검증에 새 실제 호출이 필요하면 시험 범위·기한·비용·전송을 확인해 진행한다. 실제 글·답안·계정·인증값을 공개 보고서/채팅으로 받지 않는다.
