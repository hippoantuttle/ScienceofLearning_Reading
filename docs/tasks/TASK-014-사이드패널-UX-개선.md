## 학습 흐름 및 안전 제약
- 해당 단계: 읽기 전 / 읽기·인출 / 제출 후 전 구간의 화면 구성.
- 읽기 중 AI 번역·해석·정답·내용 힌트 차단 조건: 기존 `recommendationGate`·`pilotAiStartReading` 차단, 지연 응답 폐기, 읽기 시작 후 추천 비활성을 유지한다. 화면 재배치로 AI 결과나 버튼이 읽기·구조화·Retell 화면에 노출되면 안 된다(D-3: 현행 유지).
- 제출 후 피드백 허용 조건: 저장·재조회가 일치한 제출 이후에만 피드백 영역을 표시한다(현행 유지).
- 원문 가림은 Retell에서만 적용하고 종료·복귀 시 복원한다(현행 유지).
- 비밀키·개인정보·기사 저작권: 고지 정리로 전송 범위·제공자 정보를 축소 표기하지 않는다. 개발 도구 숨김은 보안 통제가 아니며 서버 측 제한을 대신하지 않는다. 스크린샷·테스트에 실제 기사·답안을 넣지 않는다.

## 완료 기준
- AC-01: 처음 패널을 연 사용자가 스크롤 없이 「글 연결」을 찾고, 5단계 표시에서 현재 단계를 확인하며, 로그인 1회로 AI 추천·제출·피드백을 사용한다. 참가자 설정에서는 개발·모의 도구가 보이지 않는다.
- AC-02: 필수 항목 누락, 로그인 안 됨, 글 변경·탭 전환, 제출 실패·재시도 시 오류가 해당 위치에 표시되고 입력 내용이 유지된다. Retell 버튼의 결과가 누르기 전 문구와 일치한다.
- AC-03: 읽기 시작 후 AI 요청·결과 노출이 없고, 제출 전 피드백이 나오지 않으며, 가림은 Retell에서만 적용된다. 기존 관련 자동 테스트가 통과한다.
- AC-04: 키보드만으로 전체 흐름을 진행할 수 있고, 비활성 버튼의 이유가 보조기술로 전달되며, 라이트·다크 모드에서 본문·버튼 대비가 WCAG AA를 충족한다.
- v4 범위: 위 AC는 사이드패널 흐름에 적용한다. 확장 내 기록은 TASK-015, 설치용 단독 버전 검증은 TASK-017, 웹 로그인·상세 비교는 TASK-018로 검증한다. 패널 단일 로그인은 웹 자동 로그인을 뜻하지 않는다.
- 각 기준의 검증 방법: 관련 `tests/*panel*.test.cjs`·`prereading-transitions`·`submission-*` 테스트 실행(DOM id 변경 시 테스트 갱신 근거 명시), 실제 Chrome 본인 시험 1회(합성 글·합성 답안), 팀원 1~2명 사용성 관찰. 개발자 모의 확인과 사용자 실검증을 구분해 기록한다.
