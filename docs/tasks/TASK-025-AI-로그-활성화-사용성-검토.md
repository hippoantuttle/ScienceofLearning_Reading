## 배경과 목표

- 사용자의 「cloudflare 내부 로그 확인 기능을 켜주고, 사용성을 높이려면 어떻게 수정해야 하는지 검토」 지시를 이 요청으로 기록한다.
- 앞으로 오류 시점을 찾아볼 수 있도록 관련 AI Worker의 저장 로그를 켜고, 실패·재시도·결과 보존 개선안을 근거와 함께 검토한다.

## 구현 범위
- [x] `reading-ai-pilot`의 Cloudflare Workers Logs 활성화, 수집률 100%, invocation/custom logs 저장, URL query 제거.
- [x] 실제 운영 설정 재조회 및 모델을 호출하지 않는 합성 진단 요청으로 검증. 사용자 제공 저장 로그로 실제 수집 확인.
- [x] 후속 배포용 AI Wrangler 설정에 같은 수집 정책 명시.
- [x] 현재 코드의 피드백 생성·검증·화면 오류·재시도 흐름 검토 및 우선순위/검증 기준 작성.

## 제외 범위
- 무조건 자동 재시도, AI 실호출, DB/회원/회차/한도/키 변경, 제출 Worker 배포·확장 자동 교체. 새 인용 ID 계약·수정본 재평가는 후속 설계.
- 제출 Worker 등 다른 서버 로그 설정, 외부 로그 수출, 원문·답안·키·인증 헤더 수집.

## 학습 흐름 및 안전 제약
- 단계: 제출 후 피드백. 읽기 중 AI 차단·초급 후보 한정 예외·Retell 가림은 유지한다.
- 기존 코드는 고정 오류 단계만 기록함을 확인하고 수집을 켠다. 사용자 ID·본문·학습자 답안·생성 결과를 새 로그에 추가하지 않는다.
- Cloudflare 기본 invocation 메타데이터와 응용 console 로그를 구분한다. URL query는 제거하며 저장 로그에 민감정보가 없음을 무조건 보증하지 않고 실제 샘플과 후속 분류 로그의 허용 필드를 점검한다.

## 완료 기준
- AC-01: 운영 AI Worker의 enabled/logs.enabled/persist/invocation_logs=true, 수집률 1, query 제거를 재조회해 확인한다.
- AC-02: 기존 활성 버전·바인딩·기능 스위치·회차·한도 유지 여부와 무인증 요청 401을 확인한다. 로그 조회 가능 여부는 실제 결과와 권한 제한을 구분해 기록한다.
- AC-03: 개선안에 오류 분류·프롬프트/검사 계약·사용자 안내·중복/실패 처리·개인정보·수용 검증 기준이 있다. 제안과 이번 적용을 구분한다.
