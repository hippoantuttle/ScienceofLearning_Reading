## 저장·학습 원칙

- 원격 API·DB 저장 형식은 그대로다. 노드의 `order/role/source`와 연결의 `from/to/relationType`을 저장한다. 연결점을 사용한 물리적 시작 순서와 무관하게 사용자가 정한 역할/유형의 기존 논리 방향을 화면과 목록에 명시한다. 내용 해석이나 연결 정답을 AI가 판정하지 않는다.
- 어느 변의 접점을 골랐는지는 해당 훈련의 메모리에만 남고, 수동 작성/이전 구성 복귀에서도 보존한다. 저장 후 재조회에는 문장 순서·역할·연결 관계가 남으며 접점 위치나 선의 정확한 경로 재현을 약속하지 않는다. 새 좌표/접점 필드를 서버에 보내지 않는다.
- 연결 이유는 기존 `왜 이렇게 연결했나요? (선택)` 한 항목이다. 연결마다 필수 설명을 추가하거나 원문 문장을 수정하지 않는다. 유형 변경 시 기존 역할·연결을 자동으로 재해석하지 않고 구조 규칙 확인이 필요한 연결을 표시한다.
- Retell에서는 편집기를 일시 정지하고 블록·연결선·연결 목록·선 삭제 도구를 가린다. 오래된 이벤트 콜백으로 재개하거나 수정할 수 없다. 원문 재확인/복귀 경로에서만 재개한다. 종료·계정/글 무효화 때 리스너·포인터 캡처·관찰자·메모리 자료를 정리한다.
- 모든 블록/후보를 제거해도 이미 후보를 본 이력을 지우지 않는다. 배치·연결 조작으로 AI 재요청을 열지 않는다. 중급·PDF 및 기존 서버 권한/회차 정책을 바꾸지 않았다.
