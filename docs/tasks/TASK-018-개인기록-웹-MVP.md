## 배경과 목표

- 사용자와 사용 상황: 확장 단독 사용 버전에서 저장한 기록을 별도 웹에서 넓은 화면으로 찾아보고 비교한다.
- 해결할 문제: 패널의 최소 기록 조회로는 긴 답안의 나란한 비교와 누적 기록 탐색이 불편하다.
- 기대 동작: 웹 별도 로그인 → 내 기록 목록 → 최초본/선택 수정본 상세 비교. 웹이 없어도 TASK-017 확장의 기존 저장·조회는 계속 작동한다.
- 범위 출처: TASK-015 v1에 묶였던 웹 기능을 분리했다. 공통 저장 구조·API·확장 내 최소 조회는 TASK-015 v2 소유다. 웹 복습은 TASK-016 v2 후속이다.

## 구현 범위

- [ ] 기존 Supabase DB·Auth 계정과 TASK-015의 공통 API·원본/수정 이력·본인 접근권·삭제 규칙을 재사용한다. 웹 전용 복제 DB나 회원 체계를 만들지 않는다.
- [ ] 같은 계정으로 웹에서 별도 로그인·로그아웃한다. 세션 갱신·만료·재로그인·비활성 회원을 안내한다. 확장의 토큰을 URL로 전달하거나 자동 공유하지 않는다.
- [ ] 본인 기록 목록의 정렬·페이지 이동·저장 시각·글 식별 정보·수정본 유무와 빈 목록·로딩·조회 실패를 제공한다.
- [ ] 최초본과 선택한 저장 수정본을 항목별로 나란히 비교하고 변경 항목을 표시한다. 좁은 화면은 항목별 세로 보기로 제공한다. 글 정보·수정본 없는 기존 기록도 지원한다.
- [ ] 웹 새로고침·재로그인 후 동일 기록을 불러온다. 패널 실행·이전 articleSession·로컬 AI Worker에 의존하지 않는다. 웹에서 수정본을 편집하거나 AI를 자동 호출하지 않는다.
- [ ] 확장의 최소 조회는 유지하면서 선택적인 「웹에서 자세히 보기」를 추가한다. 웹 미설정·장애 때도 확장 저장·재조회가 동작한다. 웹 이동은 독해가 끝난 상태에서만 허용하고 미저장 입력을 안내한다. URL에는 민감한 답안·이메일·인증값을 넣지 않는다.
- [ ] 기존 Worker의 정확한 허용 Origin에 웹 주소를 추가하고 기존 확장 호환을 유지한다. CORS와 별개로 로그인·활성 회원·원본 소유권·DB RLS를 검증한다.
- [ ] 웹 소스·빌드·배포 설정을 확장과 분리하고 TASK-017 빌드가 웹 자원을 요구하거나 혼입하지 않는지 회귀 검증한다. 웹 공개 전에 고지·세션·오류·개인 기록 캐시 동작을 확인한다.

## 제외 범위

- 웹 복습·복습 결과 저장(TASK-016), 최초 독해·Retell·새 AI 피드백·웹 수정본 편집, 팀원 교차 열람.
- 자동 로그인 연계·초안 자동 보관·기사 전문/발췌문/AI 피드백 지속 저장. 새로운 데이터 보관 범위를 자동 추가하지 않는다.
- TASK-017 확장 단독 버전을 웹 의존형으로 바꾸는 변경, 미승인 유료 자원·웹 공개·DB 변경의 실행 승인.

## 학습 흐름 및 안전 제약

- 해당 단계: 저장된 개인 기록 조회·상세 비교. 최초 읽기·Retell과 즉시 피드백·직접 수정은 패널에 유지한다.
- 독해 중 AI·과거 답안 조회 차단을 유지한다. 확장에 웹 이동 버튼을 추가해 진행 중 답안을 열게 하지 않는다. 기록 페이지가 이미 열린 별도 창에서 사용자가 답안을 보는 것까지 차단한다고 주장하지 않는다.
- 제출 후 피드백의 기존 저장·재조회·별도 전송 동의 조건을 바꾸지 않는다. 웹 조회에는 AI 호출이 없다.
- 서버 전용 키·실제 응답·식별정보·인증값을 웹 번들·URL·공개 저장소·로그에 넣지 않는다. 사용자 식별이 가능한 분석 도구를 임의로 추가하지 않는다.
