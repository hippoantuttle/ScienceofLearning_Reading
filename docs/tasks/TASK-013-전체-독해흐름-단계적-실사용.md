# [TASK-013] 전체 독해 흐름과 단계적 실사용

## 상태 및 담당
- 상태: 요구사항 정리 및 기존 구현 대조 진행 중. 전체 흐름 미구현.
- 요청자: 사용자. 구현 담당: dev. 검토자: 미정. 요청 버전: v1.

## 배경과 목표
- 사용자가 제공한 독해훈련 순서도를 목표로 한다. 사용자 본인 1명으로 전체 흐름을 확인한 뒤 팀원 5명, 이후 참가자 14명 순서로 확대한다. 각 단계의 검증과 실제 확대는 구분한다.
- 사용자와 팀원 5명이 참가자 14명의 응답을 조회할 수 있기를 원한다. 권한 부여·회수, 동의 및 접근 기록 등 구체 설계와 검증이 필요하다.
- 사용자는 실제 글과 제출 답안을 AI 제공자에 필요한 범위로 전송하는 방향을 허용했다. 제공자 처리 조건, 전송 필드와 참가자 동의는 실사용 전 구체화한다.

## 구현 범위
- [ ] 읽기 전: 연결한 글에 맞춘 핵심 용어·최소 배경, 기존 지식 떠올리기. 주장·결론을 미리 제공하지 않는다.
- [ ] 읽기·구조화: 독해 수준별 지원 및 점진적 제거, 직접 읽기, 중심 생각, 빈 구조도에 관계 작성, 원문 없이 Retell, 감상·새 어휘·관심 분야와 제출.
- [ ] 제출 후: AI 점검과 메타인지적 읽기 전략 안내, 사용자 직접 수정, 최초본과 수정본 비교.
- [ ] 저장·복습: 개인 기록과 수정본 저장, 어려웠던 내용 기록, 시간 경과 후 복습, 핵심 주장·근거 재구성, 같은 쟁점의 다른 관점 글과 비교 및 새 글에 전략 적용.
- [ ] 사용자 본인과 권한이 부여된 팀원의 참가자 응답 조회. 참가자는 본인 자료만 조회하도록 서버에서 통제한다.
- [ ] 본인 1명 → 팀원 5명 → 참가자 14명 순으로 단계별 검증, 설치·운영·삭제 절차와 확대 기준 마련.

## 제외 범위 및 제약
- 학습효과의 입증, 동의 없는 참가자 자료 수집, 비밀키의 클라이언트 배포는 범위 밖.
- 읽기·구조화·Retell 중 AI의 요약·해석·답안·내용 힌트 금지. AI 피드백은 제출 후에만 제공한다. 원문 가림은 Retell에서만 적용한다.
- 공개 저장소·테스트·로그·결과 문서에 실제 답안, 참가자 식별정보, 비밀값을 넣지 않는다. 기사 전송 범위와 저작권, 제공자의 보관·학습 이용·처리 위치를 확인한다.

## 완료 기준
- AC-01: 본인 계정으로 순서도의 전체 단계를 실제 환경에서 순서대로 수행하고 저장·수정·복습 결과를 재조회한다. 기능별 실패·재시도도 확인한다.
- AC-02: 읽기 중 AI 개입이 차단되고 제출 전 피드백이 나오지 않으며, 읽기 전 결과에 주장·결론을 미리 제시하지 않도록 검증한다. 출력 형식 검사만으로 의미 안전성을 증명하지 않는다.
- AC-03: 사용자·승인 팀원은 허용된 참가자 자료만 조회하고 참가자·비활성자·미승인자는 타인 자료를 볼 수 없음을 실환경에서 검증한다.
- AC-04: 제공자 처리 조건, 구체적 전송 범위, 참가자 고지·동의, 보관·접근·삭제 절차와 운영 책임을 정하고 확인한다.
- AC-05: 본인 검증과 팀원 5명 점검을 각각 마친 뒤 참가자 14명의 시작·완료·중단·차단을 구분한다. 실제 결과와 한계를 비식별 집계로 보고한다.

## 현재 확인된 차이
- 현재 읽기 준비에 기존 지식 입력란은 있으나 현재 제출 계약에는 포함되지 않는다. 읽기·구조화, Retell, 최종 정리와 제출 경로가 있다.
- AI 추천은 서버에 고정된 가상 예문 기반이며 연결한 실제 글에 맞춘 추천이 아니다. 로컬 Worker 재시작 뒤 사용자 작동 확인; 실사용 AI Worker 배포는 확인되지 않았다.
- 제출 후 AI 피드백·수정본 비교·누적 학습 기록·시간 경과 복습·다른 관점 글 제공은 이 작업의 미구현 범위다.
- 현재 데이터베이스 정책은 활성 사용자 본인 자료만 조회한다. 팀원 타인 자료 열람은 구현·검증되지 않았다.
- 사용자는 합성 제출의 저장·재조회 메시지와 중복 처리를 확인했다. 오프라인 재시도와 합성 테스트 행 삭제는 미완료다.
