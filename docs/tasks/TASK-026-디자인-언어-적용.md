## 채택하지 않는 이미지 요소 (원칙 충돌 또는 범위 밖)
- 읽기·구조화 중 AI 질문 카드("공이 왜 줄었을까요?…"), AI가 표시한 원문 근거 위치, `힌트 하나 더`: **"읽기 중 AI 개입 배제"와 충돌**한다. 남색 카드 스타일도 AI 안내에 재사용하지 않는다(주의를 끄는 형태 자체가 개입을 권함).
- 확신도(확실/애매/모름)와 점검 결과 막대그래프, `통과 기준 2/3`, `추측 맞음 ✓`: 점수와 내용 정오 판정에 해당한다.
- 단어 담기, 복습 일정, Linkers 팁, 다음 읽기 예약, 포트폴리오, PDF 저장: 새 기능이다.
- `자동 저장됨` 배지: 제품은 자동 저장을 하지 않는다(미저장 경고가 있음). 표시하면 거짓 안내가 된다.
- 기사 페이지 본문 위 하이라이트 주입: 콘텐츠 스크립트 변경이라 범위 밖이다.
- "Nibble" 이름과 로고: 사용자 결정으로 채택하지 않음.

## 학습 흐름 및 안전 제약
- 해당 단계: 읽기 전 / 읽기·인출 / 제출 후 / 복습 전 화면(시각만).
- 읽기 중 차단: 새 시각 요소가 AI 결과를 더 오래 보이게 하거나 더 눈에 띄게 하면 안 된다. 초급 후보 칩에 순위·추천 표식을 붙이지 않는다. 후보 순서 외에 중요도처럼 보이는 색 차이를 두지 않는다.
- Retell: 스켈레톤은 장식일 뿐이다. 원문·후보·구조도 숨김(`hidden`, `inert`)을 CSS `display`로 덮어쓰지 않는다. `[hidden]{display:none!important}` 규칙을 유지한다.
- `완료`와 민트색은 형식·구성 규칙 충족이나 저장 성공에만 쓴다. 내용의 맞고 틀림을 암시하지 않는다.
- 합성 자료로만 검증한다. 실제 기사·답안·계정 자료는 캡처하거나 기록하지 않는다.

## 완료 기준
- AC-01: 대응표의 채택 항목이 패널 5단계와 PDF 뷰어에 일관되게 보인다. 확인 방법: 단계별 라이트·다크 캡처를 참고 이미지와 나란히 비교(design-critique).
- AC-02: 320/360/420/480px에서 가로 넘침이 없다. 하단 액션 바가 입력란이나 오류 문구를 가리지 않는다. 확인 방법: 브라우저 합성 화면에서 `scrollWidth`를 확인하고, 마지막 입력란에 포커스했을 때 보이는지 본다.
- AC-03: 새 토큰 쌍을 포함한 라이트·다크 대비가 4.5:1 이상이다(배지 글자와 배지 바탕, 칩 선택 상태 포함). 비텍스트 경계는 3:1 이상, 포커스 링이 보이고, coarse pointer에서 터치 영역은 44px 이상이다. 확인 방법: `tests/panel-ux.test.cjs` 확장과 accessibility-review.
- AC-04: 구조 유형 칩 그룹과 하단 바로 마크업이 바뀌어도 값·이벤트·탭 순서·aria 연결은 같다. 전체 `node --test` 실패 0. 확인 방법: 기존 회귀 검사 + 칩 그룹 키보드(화살표, Space) 검사 추가.
- AC-05: Retell에서 원문·후보·구조도가 계속 보이지 않는다. 읽기 중 새 AI 표시는 없다. 확인 방법: 기존 Retell·게이트 검사, 합성 화면.
- AC-06: 빌드 허용 목록에 새 파일이 있으면 반영하고, 설치본 포함 검사가 통과한다.

## 결정 사항 (2026-11-13 사용자 답변)
- **HTML 일부 변경 허용.** 구조 유형 칩 그룹, 하단 액션 바, Retell 스켈레톤, 카드 머리 배지에 필요한 마크업을 바꿀 수 있다. 값·이벤트·탭 순서·aria 연결·문구 의미는 유지한다(AC-04).
