# 로컬 AI 서버 켜기·끄기

2026-11-10 / 현재 개발 worktree 기준.

## 언제 필요한가

- 로컬 AI 서버(`127.0.0.1:8793`): 현재 개발 설정의 읽기 전 AI 추천·제출 후 AI 피드백에 사용한다. AI 버튼을 사용할 때 실제 호출 비용이 발생할 수 있다.
- 로그인·최초본 제출·수정본 저장·내 기록 조회: 배포된 Supabase/제출 Worker를 사용하므로 인터넷 연결은 필요하지만 로컬 AI 서버는 필요하지 않다. 기록 조회는 AI를 호출하지 않는다.
- 기록 조회만 실패한다면 로컬 AI 서버 시작으로 해결됐다고 가정하지 말고 로그인 상태·실제 오류·확장 서버 설정을 확인한다. 키나 작성 답안을 채팅·공개 로그에 복사하지 않는다.

## 시작

PowerShell을 열고 아래 두 명령을 실행한다. 루트 저장소가 아닌 실제 개발 worktree에서 실행해야 로컬 설정이 연결된다.

```powershell
Set-Location 'C:\Users\patri\ScienceofLearning_Reading\.claude\worktrees\local-git-status-task-progress-a93081'
npx.cmd wrangler@4.158.0 dev --config wrangler.pilot-ai.local.jsonc --local --ip 127.0.0.1 --port 8793
```

`Ready on http://127.0.0.1:8793`가 보이면 준비된 것이다. 해당 PowerShell 창은 사용 중 열어 둔다. 이 명령은 기존 설치·로컬 비밀 설정을 사용하는 현재 PC용이며 새 PC 설정을 대신하지 않는다. `npx.cmd`를 사용하면 PowerShell의 npx.ps1 실행 정책 문제를 피할 수 있다.

서버 시작만으로 AI 요청을 보내지는 않는다. 개발 전용 로컬 Worker는 인증·활성 회원 검사를 유지하지만 호출 횟수 제한이 없으므로, 추천·피드백 버튼을 누르는 것은 별도 AI 사용이다. 이 설정을 원격 배포하지 않는다.

## 종료·문제 확인

- 실행한 PowerShell 창에서 **Ctrl+C**를 누른다. 종료 후 AI 기능을 다시 쓰려면 위 명령을 다시 실행한다.
- `8793` 포트가 이미 사용 중이면 서버를 중복 실행하거나 다른 프로세스를 강제 종료하지 않는다. 기존 실행 창에서 준비 메시지를 확인한다. 포트만 바꾸면 확장의 로컬 주소와 어긋날 수 있다.
- 서버만 다시 켜는 경우 확장을 새로고침할 필요는 없다. 확장 코드·설정 변경 후 새로고침은 미저장 입력을 지울 수 있다.
- `.dev.vars`, `submission-config.local.js`, 인증값은 열람·출력·복사·커밋하지 않는다. 준비 메시지를 제외한 로그를 공유할 때도 비밀·답안이 없는지 확인한다.
