## 구현 범위
### 0단계: 결정 (2026-11-10 사용자 결정, `docs/변경이력.md` 기록)
- [x] D-1 개발 도구 노출 기준: **AI 엔드포인트가 로컬(루프백)일 때만** 표시한다. 판정은 기존 `allowLocalRepeatedRecommendations`와 같은 기준(`http:` + `127.0.0.1`/`localhost`/`[::1]`)을 공용 함수로 재사용한다. 별도 `devMode` 설정값은 추가하지 않는다.
- [x] D-2 작성 중 초안 자동 보관: **도입하지 않고 현재 상태 유지**(패널 메모리만, 닫거나 새로고침하면 사라짐). 기존 데이터 손실 경고 문구는 유지하되 2·3단계 문구 정리 시 더 짧고 눈에 띄게 표시한다.
- [x] D-3 읽기 전 AI 결과: **현행 유지**(읽기 시작 시 숨김, 읽기·구조화·Retell 중 미표시).
- [x] D-4 「기존 지식」: **제출하지 않는다.** 읽기 전 스스로 떠올리는 로컬 메모로만 쓰며 제출 계약·서버 저장 항목에 추가하지 않는다. 입력란에 "제출·저장되지 않음"을 표시한다.

### 1단계: 팀원 5명 점검 전 (구조·위계)
- [ ] 개발·모의 도구(가상 전송 미리보기, 로컬 모의 토큰, 가상 예문 추천, 합성 예시 모의 저장)를 D-1 조건(로컬 AI 엔드포인트)일 때만 접힌 「개발자 도구」 영역에 표시한다. 그 외에는 DOM에서 숨기고 해당 버튼의 동작도 비활성화한다.
- [ ] 읽기 준비 순서를 「글 연결」 → 기존 지식 쓰기(로컬 메모, 제출 안 됨) → (선택) 실제 글 기반 AI 추천 → 「읽기·구조화 시작」으로 재배치한다. 글 연결 전에는 이후 항목을 비활성화하고 이유를 표시한다.
- [ ] 로그인을 상단 계정 바 하나로 통합한다(로그인 상태·이메일·로그아웃). AI 추천·제출·피드백은 이 상태를 공유한다.
- [ ] 단계 표시를 5단계(읽기 준비 / 읽기·구조화 / 다시 말하기 / 정리·제출 / 피드백·수정)로 확장하고 현재 단계를 `aria-current="step"`으로 표시한다.
- [ ] 버튼 위계(기본·보조·위험)와 최소 디자인 토큰(색·간격·테두리, 라이트/다크)을 `sidepanel.css`에 정의한다.

### 2단계: 단계별 화면
- [ ] 구조도를 시각적 도식(두 상자 + 관계 설명 연결)으로 표시한다. 유형 선택에 따라 레이블만 바뀌고 내용은 채우지 않는다.
- [ ] 「작성 내용 점검」과 「Retell로 이동」을 통합한다. 누락 시 해당 칸으로 포커스를 옮기고 인라인 오류를 표시한다.
- [ ] Retell 버튼의 결과를 누르기 전에 알 수 있게 한다(예: 「원문 다시 보기 · 재확인으로 기록됨」). 「훈련 종료」는 확인 후 초기화하며 읽기 화면으로 보내지 않는다.
- [ ] 최종 확인의 완료성 버튼을 기본 「제출」 하나로 정리한다. 동의 체크를 바로 위에 두고 "(설정 전 비활성)" 제목을 실제 상태에 맞춘다. 영수증은 `submissionId` 대신 사람이 읽는 저장 확인 문구로 표시한다.
- [ ] 최초본/수정본 비교를 항목별 좌우 보기로 바꾸고 바뀐 항목을 강조한다. 이후 수정본 저장·재조회 화면으로 재사용할 수 있게 구성한다.

### 3단계: 문구·접근성
- [ ] 영역별로 반복되는 전송·보관 고지를 한 줄 요약 + `<details>` 「자세히」로 정리한다. 고지의 실제 내용(전송 대상·제공자·확인 중 상태)은 줄이지 않는다.
- [ ] 상태 메시지를 성공·주의·오류 3종으로 통일하고, 오류는 해당 버튼 옆 인라인에 표시한다. 상단 `#status`는 전체 진행 상태만 표시한다.
- [ ] 비활성 버튼에 `aria-describedby`로 이유를 연결한다. 숨김 상태의 live 영역 문제(`#ai-result`)를 수정한다. `confirm()` 문구를 짧게 줄인다.
- [ ] 용어를 통일한다(중심 생각 / 핵심 정보·보조 정보 / 관계 설명 / 다시 말하기(Retell)). "두 카드" 등 화면과 맞지 않는 표현을 제거한다.

## 학습 흐름 및 안전 제약
- 해당 단계: 읽기 전 / 읽기·인출 / 제출 후 전 구간의 화면 구성.
- 읽기 중 AI 번역·해석·정답·내용 힌트 차단 조건: 기존 `recommendationGate`·`pilotAiStartReading` 차단, 지연 응답 폐기, 읽기 시작 후 추천 비활성을 유지한다. 화면 재배치로 AI 결과나 버튼이 읽기·구조화·Retell 화면에 노출되면 안 된다(D-3: 현행 유지).
- 제출 후 피드백 허용 조건: 저장·재조회가 일치한 제출 이후에만 피드백 영역을 표시한다(현행 유지).
- 원문 가림은 Retell에서만 적용하고 종료·복귀 시 복원한다(현행 유지).
- 비밀키·개인정보·기사 저작권: 고지 정리로 전송 범위·제공자 정보를 축소 표기하지 않는다. 개발 도구 숨김은 보안 통제가 아니며 서버 측 제한을 대신하지 않는다. 스크린샷·테스트에 실제 기사·답안을 넣지 않는다.

## 완료 기준
- AC-01: 처음 패널을 연 사용자가 스크롤 없이 「글 연결」을 찾고, 5단계 표시에서 현재 단계를 확인하며, 로그인 1회로 AI 추천·제출·피드백을 사용한다. 참가자 설정에서는 개발·모의 도구가 보이지 않는다.
- AC-02: 필수 항목 누락, 로그인 안 됨, 글 변경·탭 전환, 제출 실패·재시도 시 오류가 해당 위치에 표시되고 입력 내용이 유지된다. Retell 버튼의 결과가 누르기 전 문구와 일치한다.
- AC-03: 읽기 시작 후 AI 요청·결과 노출이 없고, 제출 전 피드백이 나오지 않으며, 가림은 Retell에서만 적용된다. 기존 관련 자동 테스트가 통과한다.
- AC-04: 키보드만으로 전체 흐름을 진행할 수 있고, 비활성 버튼의 이유가 보조기술로 전달되며, 라이트·다크 모드에서 본문·버튼 대비가 WCAG AA를 충족한다.
- 각 기준의 검증 방법: 관련 `tests/*panel*.test.cjs`·`prereading-transitions`·`submission-*` 테스트 실행(DOM id 변경 시 테스트 갱신 근거 명시), 실제 Chrome 본인 시험 1회(합성 글·합성 답안), 팀원 1~2명 사용성 관찰. 개발자 모의 확인과 사용자 실검증을 구분해 기록한다.
