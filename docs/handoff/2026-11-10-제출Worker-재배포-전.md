## 6. 이번에 발견한 결함 (원인과 교훈)
1. **Chrome은 확장 페이지의 GET에 `Origin` 헤더를 붙이지 않는다.** Origin 없음 → 제출 Worker가 `forbidden`. 로그인 직후 멤버십 GET과 제출 후 재조회 GET이 모두 해당. (POST에는 붙음.)
2. **Cloudflare Workers는 `fetch`의 `redirect:'error'`를 지원하지 않는다**(TypeError). 제출 Worker는 인증된 모든 요청이 503이 될 상황이었다. Node 테스트로는 못 잡고 `wrangler dev`/배포 환경에서만 드러난다.
3. 오류 원인이 구분되지 않아 디버깅이 길어졌다 → 서버가 단계별 안전 코드를 반환하도록 개선.
- 교훈: 실제 Chrome·Workers 런타임에서의 확인이 없으면 TASK-011 같은 "로컬/모의 통과"는 완료가 아니다.

## 7. 다음 작업: 제출 Worker 재배포 (승인 대기)
대상은 `reading-submissions-pilot` 하나. AI Worker 배포·Secret 값 변경·실제 참가자 접촉은 제외. **배포는 사용자가 직접 실행**한다.

0. **사전 점검(사용자)**: `npx wrangler@4 whoami`, `npx wrangler@4 deployments list --name reading-submissions-pilot`(롤백용 버전 ID 메모), `npx wrangler@4 secret list --name reading-submissions-pilot`(Supabase 공개 키 Secret 이름 존재 확인: `SUPABASE_ANON_KEY` 또는 `SUPABASE_PUBLISHABLE_KEY`), 대시보드 변수 확인.
1. **배포(사용자, 승인 후)** — 반드시 worktree 폴더에서:
   ```bash
   npx wrangler@4 deploy --config wrangler.submissions.jsonc --keep-vars
   ```
2. **스모크(토큰 불필요, 요청 시 에이전트가 실행)**
   - OPTIONS + 확장 Origin → 204
   - GET `?membership=1`, Origin 없음, 가짜 토큰 → **401**(수정 전 503)
   - GET `?membership=1`, Origin 없음, 토큰 없음 → 401(수정 전 403)
   - GET, 다른 Origin → 403 / POST, Origin 없음 → 403
3. **Chrome 실검증(사용자, 합성 계정 A만)**: 로그인 → 합성 내용 작성 → 제출 → "저장 및 재조회 확인" 메시지 → 같은 시도 재제출(중복 처리) → 네트워크 차단 후 제출(입력 유지·재시도).
4. **정리(사용자)**: Supabase 대시보드 `pilot_submissions`에서 합성 계정 A의 행 삭제.
5. **롤백**: `npx wrangler@4 rollback <버전ID> --name reading-submissions-pilot`. Supabase 데이터는 이번 배포로 바뀌지 않는다.
