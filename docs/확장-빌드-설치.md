## 본인 검증용 Chrome 설치

1. 사용 중인 확장의 미저장 내용을 먼저 보존한다. **기존 개발 프로필과 분리된 Chrome 검증 프로필**을 사용한다. 기존 개발 확장을 제거하거나 같은 프로필에서 로드 경로를 바꾸지 않는다.
2. ZIP을 받은 경우 고정 폴더에 압축을 풀어 `manifest.json`이 들어 있는 폴더를 찾는다. ZIP 자체를 Chrome에 드래그해 설치하지 않는다. 로컬 산출물은 `dist/<label>/extension`이 해당 폴더다.
3. 검증 프로필에서 `chrome://extensions`의 개발자 모드를 켜고 「압축해제된 확장 프로그램을 로드합니다」로 해당 폴더를 선택한다. 자동화로 설치할 때는 설치 직전 별도 승인한다.
4. 확장 ID가 `jenapgoakhnmlmjcdnkfakkkgjobbfbb`인지 확인한다. 공개 manifest 키로 고정하며 서명 개인키를 생성하지 않는다. 서버 Origin 설정은 `chrome-extension://jenapgoakhnmlmjcdnkfakkkgjobbfbb`와 일치해야 한다.
5. 일반 웹 글에서 확장 아이콘을 눌러 패널을 연다. 검토 전용본은 직접 작성한 합성 글로 읽기·Retell·복원만 점검한다. 실제 계정·답안·외부 기사 전문을 검증 자료로 저장하지 않는다.

업데이트 전 미저장 내용을 보존하고 새 산출물·보고서·해시를 별도 label로 보관한다. 같은 검증 프로필의 기존 고정 설치 폴더에 새 검증본을 적용하고 확장 새로고침 후 ID·버전을 다시 확인한다. 복구도 보존한 이전 산출물로 같은 절차를 따른다. 패널을 닫거나 확장을 새로고침하면 미저장 초안·토큰이 사라질 수 있어 재로그인이 필요하다. 서버 저장 완료가 확인된 기록은 로그인 후 내 기록에서 다시 확인한다.

## AI 원격 배포 준비안과 실행 상태

- 새 대상은 `wrangler.pilot-ai.jsonc`의 `reading-ai-pilot`이다. 기존 두 Worker를 덮어쓰지 않는다. 엔트리는 `server/ai/pilot-worker.mjs`이며 DB 스키마 변경은 필요하지 않다.
- 공개 변수는 기존 Supabase URL·위 확장 Origin·사용자 일일 5회/전체 일일 100회다. Durable Object `PILOT_BUDGET`/`PilotBudget`이 예약을 원자적으로 수행하며 실패도 한도를 사용한다. 금액 상한은 이 호출 횟수만으로 보장되지 않는다.
- 서버 Secret은 `DEEPSEEK_API_KEY` 및 `SUPABASE_PUBLISHABLE_KEY`(제공된 anon 키도 기존 코드에서 허용)다. 제공자 비밀키는 채팅·Git·클라이언트로 전달하지 않고 Cloudflare의 Secret 입력으로 설정한다.
- 1차 배포는 기본 `PILOT_AI_ENABLED=false`로 유지한다. `PILOT_ARTICLE_ENABLED`·`PILOT_FEEDBACK_ENABLED`도 기본 비활성이다. 배포 승인과 실제 AI 활성화·호출 승인은 구분한다.
- 실제 AI 검증을 승인할 때 전송 범위는 직접 작성한 비민감 합성 본문, 피드백에서는 본문과 저장 확인된 본인 답안이다. URL·쿠키·기사 제목은 AI로 보내지 않는다. 본인 계정·명시 동의·정확한 Origin·활성 멤버십·한도·읽기 중 차단을 유지한다.
- 승인 후 Wrangler 명령의 현재 도움말·로그인 계정·대상·dry-run을 확인하고 새 Worker만 배포한다. 비활성·미인증/잘못된 Origin의 거절을 먼저 검증한다. 실제 활성화·유료 호출 전에 비용·합성 계정·정리 범위를 확정한다. 이 문서는 실행 승인이나 실제 배포 확인을 뜻하지 않는다.

근거: [Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel), [Supabase API keys](https://supabase.com/docs/guides/getting-started/api-keys), 로컬 Worker 코드·기존 공개 배포 설정·이번 사용자 원격 Worker 목록 확인.
