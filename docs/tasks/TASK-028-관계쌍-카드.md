## 현재 구조 (검토 근거)
- 초급 구조도는 이미 쌍 정보를 갖고 있다. 노드마다 역할(`primary`/`support`)이 있고, 연결(`edges`)마다 출발·도착·관계 유형이 있다(`reading-support-contract.js`). 구조 유형마다 관계는 하나로 고정되어 있다(`relations`). 화면만 역할별 칸으로 나뉜다(`guided-board.js`).
- 저장되는 `primary`·`support` 문자열은 `textFields`가 역할별로 줄바꿈해 합친 값이다. 서버 Worker는 `learning-support.js`로 같은 값을 다시 계산해 일치하는지 확인한다. → **저장 문자열 형식을 바꾸지 않는다.**
- 중급은 `primary`·`support`·`relation` 입력란이 하나씩이고, 서버에도 문자열 하나씩 저장된다. 제출 후 피드백·수정본 화면도 하나씩 다룬다.

## 구현 범위
### 초급 1단계: 쌍 묶음 표시
- [ ] R-1 구조화 보드에서 역할별 칸 대신 관계 카드 목록을 보여 준다. 카드 하나 = 상위 역할 문장 하나(주장/원인/문제 쪽)와 연결된 상대 역할 문장들.
- [ ] R-2 `＋ 관계 추가`로 빈 카드를 만들고 양쪽에 문장을 놓으면 그 구조 유형의 고정 관계로 연결된다(기존 `place`·`connect` 동작을 조합). 관계 유형을 고르는 기능은 없다(서버 변경 범위).
- [ ] R-3 짝이 없는 문장은 `배치할 문장`에 남는다. 한 문장이 여러 카드에 연결되면 각 카드에 `같은 문장` 표시를 한다.
- [ ] R-4 키보드로 선택·놓기·연결·제거가 가능하다(기존 보드 수준 유지).
- [ ] R-5 정리 화면·내 기록의 구조도 표시도 저장된 `edges`로 쌍을 묶어 보여 준다.
- [ ] R-6 저장 형식(`nodes`·`edges`·`textFields`), 노드 8개·연결 16개 제한, 임시저장 복원은 그대로다.

### 중급 A안: 여러 관계 작성
- [ ] M-1 구조화 화면에 관계 카드(주장 / 근거 / `왜 이렇게 연결했나요? (선택)`)를 두고 `＋ 관계 추가`·카드 삭제를 제공한다. 최소 1개, 최대 5개.
- [ ] M-2 저장 때 각 칸을 정해진 형식으로 합쳐 기존 `primary`·`support`·`relation` 문자열로 보낸다. 카드가 1개이면 지금과 같은 문자열(표시 없음)을 보내 기존 기록과 호환한다.
- [ ] M-3 정리 화면·내 기록·피드백 수정본 화면은 그 형식을 나눠 카드로 보여 준다. 형식이 맞지 않는 기존 값은 카드 1개로 보여 준다.
- [ ] M-4 학습자가 구분 표시와 같은 글자를 입력해도 경계가 깨지지 않도록 저장 전에 처리한다.
- [ ] M-5 임시저장(`training-draft.js`·`draft-panel.js`)이 카드 여러 개를 담고 되살린다. 형식 검사도 넓힌다.
- [ ] M-6 필수 검사: 카드마다 주장·근거를 모두 쓰거나 모두 비워야 한다. 모두 빈 카드는 저장할 때 뺀다.

## 학습 흐름 및 안전 제약
- 읽기 중 AI 개입 배제 유지. AI는 초급 문장 후보만 제공하고 쌍을 지어 주지 않는다. 쌍 구성은 학습자가 한다(AGENTS.md 초급 예외 범위).
- Retell 중 카드·구조도 가림 유지.
- AI 피드백은 합쳐진 문자열을 받는다. 쌍별 피드백은 보장하지 않으며 화면에서 그렇게 안내하지 않는다.
- 개인정보·비밀값·실제 학습자 응답을 코드·테스트·문서에 넣지 않는다.
