## 원격 검증의 별도 선행 조건
아래는 v5 시점의 선행 조건이다. 이후 v7 사용자 지시로 DB/Worker 적용·합성 원격 검증·후보 활성화를 진행했다. 현재 완료 범위와 남은 검증은 위 서버 적용 결과가 우선한다.

1. 기존 DB에 `20261112040245_optional_relation.sql` → `20261112042928_learning_support.sql` 순서로 적용. 후자는 이전 비공백 제약이 남아 있으면 적용을 거절한다. 기존 행은 v1/null 유지. 파괴적 롤백으로 컬럼을 제거하지 않는다.
2. 제출 Worker 및 후보/피드백 AI Worker를 배포하되 `PILOT_GUIDED_CANDIDATES_ENABLED=false` 유지. 기존 회차·기한·비용 한도를 바꾸지 않는다. 인증된 capability 응답, Origin·비인증·타인·비활성 차단을 확인한다.
3. 승인된 소수 검증에서만 서버 스위치와 클라이언트 `guidedReadingEnabled`를 켠다. 예전 클라이언트의 AI 피드백 형식 차이와 빈 설명 편집 한계는 기존 인계를 따른다.
4. 전송이 허용된 합성 글로 후보 품질·지연·401/403/429·재시도·직접 전환을 확인한다. 문장 후보가 맥락을 보존하고 연결할 정보를 제공하는지는 사람이 판단해야 한다.
5. 후보를 본 뒤 모두 제외/직접 작성으로 전환해도 노출 이력이 유지되는지, v2 원본과 최초 그래프·출처가 재조회되는지 확인한다. 수정본은 텍스트만 바뀌고 최초 그래프는 보존되어야 한다.
6. 실제 모델 피드백이 Retell만 평가하고, 원문 발췌를 창작으로 취급하거나 빈 선택 설명을 감점하지 않는지 확인한다. 모델 입력/출력·실제 답안을 공개 로그에 남기지 않는다.

최초 로컬 개발만으로는 원격 적용 권한이 없었고, 후속 v7 명시 지시로 이번 서버 적용·합성 검증·후보 활성화가 승인됐다. 실제 학습자 자료 전송·main 병합·push 권한으로 확대하지 않는다. 남은 Google/모델/Chrome 검증 전에는 전체 수용 완료로 표시하지 않는다.
