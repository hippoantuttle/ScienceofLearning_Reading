## 비활성 배포·제한 실험 절차 (2026-11-05, 미실행)
1. 비활성 배포는 사용자 별도 승인 후에만. `wrangler.jsonc`의 `EXPERIMENT_ENABLED=false`, Worker 이름과 대상 계정·기존 동명 Worker 유무를 확인한다. Wrangler 인증이 없다면 사용자가 본인 브라우저에서 직접 `npx wrangler@4.157.0 login`을 수행하고 `npx wrangler@4.157.0 whoami`로 계정명·ID를 확인한다. 계정 식별자가 여러 개면 사용자가 대상 선택을 확인하기 전 배포하지 않는다. 인증 정보는 공유하지 않는다.
2. 검토·승인 후 저장소에서 `npx wrangler@4.157.0 deploy --config wrangler.jsonc` 실행. 생성·수정되는 리소스를 확인하고 배포 출력 및 Cloudflare Workers 대시보드에서 실제 URL을 읽어 확인한다. 동명 Worker가 이미 있으면 덮어쓰기 전에 중단해 사용자에게 확인한다. 첫 배포가 workers.dev 등록을 요구하면 사용자에게 절차를 확인한다.
3. 비활성 점검: Secret은 기본 미등록이므로 미인증 요청은 401. 별도 승인 후 사용자가 ACCESS_TOKEN을 Secret으로 직접 등록한 경우에만 인증된 `{}` 요청이 503인지 확인한다. 등록 전에는 인증된 503 확인 불가. 로컬의 가상 토큰과 혼동하지 않는다. 키·토큰·응답 전문을 로그나 채팅에 남기지 않는다.
4. 실호출 준비: 15분·3회 변경본은 사용자 승인 후 비활성 재배포됐다. 새 활성 버전의 `false`, 두 Secret 이름, BUDGET 바인딩은 확인했으나 실제 namespace ID 및 기존 누적 횟수의 재배포 전후 동일성은 미검증이다. 저장소/namespace 삭제·재생성으로 한도를 초기화하지 않는다. 실호출 조건이 충족되거나 변경 승인되기 전 활성화 금지.
5. 제한 실험 실행(승인 전 실행 금지): 사전에 비용·데이터 처리 조건과 PM 비공개 열람 방법을 확인한다. CMD에서 `powershell -NoProfile -Command "[DateTimeOffset]::UtcNow.AddMinutes(15).ToUnixTimeMilliseconds()"`로 시각을 산출하고, 사용자가 해당 Worker의 `EXPERIMENT_EXPIRES_AT`에 그 13자리 값을 넣고 `EXPERIMENT_ENABLED=true`를 적용한다. 최대 미래 허용 15분이며 비어 있거나 만료·너무 먼 값이면 호출하지 않는다. 활성 배포 버전·두 Secret 이름과 유효시각을 확인한 다음 CMD에서 `powershell -NoProfile -File scripts\request-experiment-once.ps1`을 한 번 실행한다. 실험 전용 ACCESS_TOKEN을 숨김 입력한다. 결과와 토큰 사용량은 화면에만 보이며 화면·출력 기록에 주의하고 응답 전문을 공개하지 않는다. 오류·timeout도 1회를 소비할 수 있으므로 재시도하지 않는다. 요청 후 성공·실패와 무관하게 사용자가 즉시 false로 변경·적용하고 배포 버전의 false를 재조회한다. 유효시간·3회 제한은 false 자동 복귀나 진행 중 호출 취소를 보장하지 않는다.
6. 회당 0.10달러 예약은 공급자 과금 상한을 입증하지 못한다. US$1 상한은 미검증이며 동시 호출·재시도 및 동일 키를 다른 경로에서 쓰는 비용도 고려해야 한다. 운영 로그/응답 크기·timeout 및 데이터 보관·학습 이용 정책, 사용량 기록 범위도 실호출 전에 확인한다.
