# [TASK-015] 수정본 저장 기반과 확장 내 최소 재조회

## 배경과 목표

- 사용자와 사용 상황: 패널에서 한국어 글을 읽고 최초 답안을 제출한 사용자가 직접 수정본을 저장하고, 확장을 다시 열어 자신의 기록을 조회한다.
- 해결할 문제: 수정본은 패널 메모리에만 있고, 제출 API는 특정 세션 한 건만 조회한다. v1은 기록 조회에 웹 구축이 필요했다.
- 기대 동작: 패널 최초 제출·재조회 → 기존 피드백·직접 수정 → 명시적 수정본 저장 → 확장 재열기·로그인 → 최근 기록 선택 → 최초본/저장 수정본 간단 확인. 웹사이트를 열지 않는다.
- 상위 목표: TASK-013 v3. 순서: TASK-015 → TASK-014 v4 잔여 → TASK-017 확장 단독 빌드·검증 → TASK-018 웹 MVP → TASK-016 v2 웹 복습.
- 단독 사용은 별도 웹사이트와 사용자의 로컬 개발 서버 없이 확장과 원격 DB·AI 서버로 사용하는 의미다. 완전 오프라인·서버 없는 제품은 범위 밖이다. 실제 설치 산출물과 원격 연결은 TASK-017에서 검증한다.

## 구현 범위

### 1. 저장 구조·공통 API

- [ ] 기존 Supabase 프로젝트·Auth 계정·활성 멤버십·최초 제출을 재사용한다. 새 DB나 별도 회원 체계를 만들지 않는다.
- [ ] 최초 제출을 변경하지 않고 원본과 연결된 수정본을 별도 이력으로 추가 저장한다. 수정 대상은 현재 UI의 중심 생각·핵심 정보·보조 정보·관계 설명·Retell이며 나머지 최초 제출 필드는 유지한다.
- [ ] 원본 제출 식별자·작성자·버전 식별자·서버 저장 시각을 관리한다. 같은 요청 재시도는 중복 버전을 만들지 않고 다른 내용을 같은 식별자로 보내면 충돌을 알린다.
- [ ] 본인 기록 목록·최초본·수정 이력 조회와 수정본 저장을 공통 API로 제공한다. 목록은 필요한 요약 필드만 반환하고 정렬·페이지 구분을 지원하며 기존 제출 계약과 호환한다. 이후 웹도 이 API를 재사용한다.
- [ ] 기존 제출 Worker 확장을 기본안으로 삼고 정확한 확장 Origin을 관리한다. 웹 Origin 추가는 TASK-018에서 한다. 로그인·활성 회원·원본 소유권을 검증하고 DB RLS에서도 강제한다. 본인 수정본을 타인의 원본에 연결할 수 없게 한다.
- [ ] 최초 제출의 UPDATE 권한을 넓히지 않는다. 사용자가 저장된 수정본의 소유자·원본 연결을 바꿀 수 없게 한다.

### 2. 패널 저장·기록 이동

- [ ] 저장·재조회가 확인된 최초 제출에만 수정본 저장을 허용한다. 기존 피드백·직접 수정과 간단 비교는 유지한다.
- [ ] 「수정본 저장」의 진행·성공·실패와 미저장 상태를 구분한다. 재조회가 저장 내용과 일치해야 완료로 표시한다. 실패·토큰 만료 시 입력을 유지하고 재시도·재로그인을 안내한다.
- [ ] 「내 기록」은 확장 내부 기록 화면을 연다. 미저장 입력이 있으면 먼저 저장하거나 이동 시 사라짐을 확인한다. 새 독해 중에는 과거 답안을 열 수 없고, 훈련 종료·가림 복원 후에만 기록으로 이동한다.
- [ ] 작성 중 초안 자동 보관과 기존 지식 제출은 추가하지 않는다. 웹 링크·넓은 상세 비교·검색 대시보드는 TASK-018로 미룬다.

### 3. 확장 내 최소 기록 조회

- [ ] 기존 확장 계정 로그인·로그아웃을 재사용하고 만료·재로그인·비활성 회원을 안내한다. 패널 종료 후 필요하면 다시 로그인한다. 장기 로그인은 필수가 아니다.
- [ ] 최근 본인 기록의 저장 시각·글 식별 정보·수정본 유무를 보여준다. 빈 목록·로딩·실패·추가 목록 조회 상태를 제공한다.
- [ ] 선택 기록의 최초본과 선택한 저장 수정본을 항목별로 이어서 간단 확인한다. 수정본 없는 기록도 표시하고 현재 미저장 수정과 저장본을 구분한다.
- [ ] 조회는 이전 articleSession·제출 flow·로컬 AI Worker·웹사이트 없이 동작한다. 확장 재열기·새로고침·재로그인 후 원격 DB에서 동일 기록을 불러온다. 저장 답안을 새 독해의 입력으로 자동 채우지 않는다.

### 4. 보관·삭제·호환

- [ ] 글 식별 정보는 공개 글 제목·출처 URL의 최소 범위로 설계한다. 자격정보·개인 식별 쿼리를 보관하지 않는다. 기존 기록에는 「글 정보 없음」을 허용하며 실제 글을 임의 복원하지 않는다.
- [ ] 기사 전문·발췌문·AI 피드백 지속 저장을 추가하지 않는다. 기록 조회 시 AI를 자동 호출하지 않는다. 기존 패널 피드백의 동의·전송 범위를 유지한다.
- [ ] 조기 삭제 요청과 파일럿 종료 후 30일 이내 삭제 절차에 수정본·글 식별 정보도 포함한다. 담당은 사용자다. 관리자 처리 경로·백업 보존 한계를 문서화하고 합성 데이터 삭제·재조회를 검증한다. 참가자용 삭제 UI는 필수가 아니다.

## 학습 흐름 및 안전 제약

- 해당 단계: 제출 후 수정본 저장과 개인 기록 조회. 읽기·구조화·Retell 중 AI 요청·결과·지연 응답 차단과 Retell만 가림을 유지한다.
- 독해 진행 중 과거 답안·피드백 기록 조회도 차단한다. 종료 시 입력 손실 안내와 원문 복원을 처리하고 나서 기록 화면을 연다.
- 제출 후 피드백은 저장·재조회 일치 및 별도 동의 조건을 유지한다. 기록 조회에는 AI 호출이 없다.
- 서버 전용 키를 확장에 넣지 않는다. 실제 응답·식별정보·인증값을 URL·로그·공개 저장소에 기록하지 않는다. 합성 데이터로 검증한다.
